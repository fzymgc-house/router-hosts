<objective>
Add the keyset cursor to the published `storage.HostProjection` interface, implement it in
the SQLite backend, reimplement `ListAll` on top of it, and wire it end-to-end through one
real consumer — `WatchHosts`' snapshot — so a page travels interface → SQL → gRPC stream →
wire in a single proven slice.

This is the phase's tracer. It is production-quality, not a prototype: the page function it
publishes is the final shape every later plan builds on, and its `<verify>` is a real
end-to-end check of the one path (a WatchHosts snapshot served entirely through pages), not
a set of per-layer unit tests.

Purpose: LAZY-01 demands a published interface change, not an internal optimization. Proving
that interface end-to-end on one consumer before expanding to `ExportHosts`, the hook count,
and the in-package filters means an architectural dead-end costs one commit instead of five.

Output: `ListPage` on `HostProjection` and on `sqlite.Storage`; `ListAll` as a drain loop;
`sendSnapshot` paging; cross-backend conformance tests.
</objective>

    <option id="tuple-4">
      <name>Four-value tuple — `ListPage(ctx, after ulid.ULID, limit int) (entries []domain.HostEntry, next ulid.ULID, done bool, err error)`</name>
      <pros>Exactly D-05's sketched shape. No new named type on the published surface. `next` and `done` are separately readable, so a caller cannot mistake a zero cursor for exhaustion. Trivially resumable across a gRPC reconnect — the caller persists one ULID string.</pros>
      <cons>Four return values is at the edge of Go style. `next` is meaningless when `done` is true, an ambiguity the doc comment must carry rather than the type.</cons>
    </option>

      <name>Result struct — `ListPage(ctx, after ulid.ULID, limit int) (storage.HostPage, error)` where `HostPage{Entries []domain.HostEntry; Next ulid.ULID; Done bool}`</name>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gRPC client → `WatchHosts` | mTLS-authenticated client opens a snapshot stream. No new request field is added; page size is server-internal. |
| server code → `storage.HostProjection.ListPage` | Internal Go call. `limit` originates from a server-side constant/var, never from the wire. |
| `sqlitex.Pool` connection ↔ page fetch | Each `ListPage` call checks out and returns a pooled connection, so pages do not share a read transaction. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-04 | Denial of Service | single deep aggregate replayed inside one page fill | medium | accept | Pages bound entry COUNT, not the event count replayed for one deep aggregate (D-06). Documented in `ListPage`'s doc comment (D-09) rather than mitigated; issue #401 tracks the eventual atomic read. |
| T-02-06 | Information disclosure | future wire-exposure of page size | low | accept | `proto/router_hosts/v1/hosts.proto` carries no page-size field today, verified in RESEARCH.md.
