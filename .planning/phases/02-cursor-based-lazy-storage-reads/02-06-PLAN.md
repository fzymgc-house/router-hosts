<objective>
Turn the benchmark from a measurement someone can run into a gate that runs itself, and prove
the gate fails before trusting it to pass.

D-13: the benchmark lives behind its own build tag with its own CI job folded into
`ci-go-complete`, mirroring the tier pattern Phase 1 established. The deciding argument is
technical rather than aesthetic — `task test` runs with `-race`, which both makes a 10k
fixture slow and perturbs allocation accounting, the exact quantity being measured.

Phase 1's D-16 governs acceptance: any gate this phase writes must itself be demonstrated
RED. Durable memory `cq0rfk0qjc` sharpens it — a green run on macOS proves nothing about
Linux CI. The RED proof therefore has to happen on a Linux runner, which is why this plan
carries a blocking human checkpoint rather than claiming completion from a local run.

Purpose: an ungated benchmark is a number in a SUMMARY that nobody re-runs. A gated one that
was never shown to fail is worse — it teaches the next maintainer that the tier is noise.

Output: a task target, a CI job, an extended wiring invariant, a proven-RED record, and
contributor documentation.
</objective>
