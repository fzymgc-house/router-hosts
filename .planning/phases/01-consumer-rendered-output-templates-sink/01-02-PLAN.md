# Phase 1 Plan 02 — Template Data Contract — Version Gate and Published Field Set

<objective>
Turn the template data shape proven by the tracer into an explicit, versioned,
published compatibility surface, and make a version mismatch a loud refusal instead
of a silently wrong render.

Purpose: TMPL-02 is the phase's highest-risk requirement. Once consumers depend on a
field set, that set becomes a compatibility obligation the proto contract does not
cover. D-05 converts a future field rename from a silent wrong-render into a startup
error.
Output: contract-version declaration and enforcement in `internal/client/template`,
`docs/reference/template-contract.md`, and three shipped example templates.
</objective>

  <behavior>
- A template source containing a `contract_version` named block whose body is `1` yields the declared version string "1", with surrounding whitespace trimmed.
- A template source with no such named block causes `DeclaredVersion` to return a non-nil error naming the block that must be declared.
- `RequireVersion("1", "1")` returns nil.
- `RequireVersion("1", "2")` returns a non-nil error whose message contains both "1" and "2".
- `RequireVersion("1.0", "1")` returns a non-nil error — comparison is exact string equality, not a semver range match.
- Running `render --template <file>` with an undeclared version returns an error and makes no gRPC call.
- Running `render --template <file>` whose declared version differs from the server's returns an error, and no artifact is written even when `--out` is supplied.
  </behavior>
  <action>
1. `internal/client/template/template.go` — add the exported constant
`ContractVersionBlockName = "contract_version"` with a doc comment stating that
every consumer template must declare the contract version it targets in a named
block of that name. Add
`func DeclaredVersion(tmpl *texttemplate.Template) (string, error)`: call
`tmpl.Lookup(ContractVersionBlockName)`; when the lookup returns nil, return
`oops.Errorf` with a message naming the block and showing the exact literal a
template must contain to declare version 1; otherwise execute the looked-up
sub-template with nil data into a local `bytes.Buffer`, wrap any execution error
with `oops.Wrapf(err, "evaluate contract version block")`, and return
`strings.TrimSpace(buf.String())`. Add
`func RequireVersion(declared, served string) error` performing exact string
equality and, on mismatch, returning an `oops.Errorf` whose message states the
version the template targets, the version this server serves, and points at
`docs/reference/template-contract.md`. Do not accept prefixes, ranges, or empty
strings as wildcards — 01-RESEARCH.md's Security Domain (V5) calls for exact match.

2. `internal/client/commands/render.go` — after `template.Parse` succeeds and
before `newClientFromFlags()` is called, call `template.DeclaredVersion` and
return its error unchanged if it is non-nil, so a template missing the
declaration costs nothing on the wire. After the stream drains and the
`SnapshotComplete` terminator is captured, and before `template.Render` is
called, call `template.RequireVersion(declared, complete.GetContractVersion())`
and return its error. Nothing may be written to `--out` on either failure path.

3. Tests. `internal/client/template/template_test.go`: add
`TestTemplateVersion_DeclaredFromNamedBlock`,
`TestTemplateVersion_MissingBlockFails`,
`TestTemplateVersion_ExactMatchOnly` (table-driven over matching, differing, and
dotted-variant version pairs). `internal/client/commands/render_test.go`: add
`TestRender_RefusesUndeclaredVersion` and `TestRender_RefusesVersionMismatch` —
the mismatch case constructs a template declaring a version that differs from
`server.TemplateContractVersion`, pre-writes a known artifact into `t.TempDir()`,
runs `render --template ... --out ...`, and asserts both that the command errors
and that the pre-written artifact bytes are unchanged. Update every template
fixture already present in `render_test.go` and `template_test.go` so it declares
the current contract version; those fixtures are now invalid without it.

Commit as `feat(client): enforce template contract version`.

1. A statement that this page — not any Go struct — defines what a template may

and of the release version.

2. "Contract version 1" section: a table of the top-level fields `.Entries`,
`.Count`, `.GeneratedAt`, `.ContractVersion` with their Go types and meanings,
and a table of per-entry fields `.IPAddress`, `.Hostname`, `.Aliases`, `.Tags`,

the server serves, and show the shape of that error.

4. "Version change policy": adding a field is a compatible change and does not
bump the version; renaming or removing a field bumps it; a bump means every
consumer template must be updated and redeclared.

5. "Data is delivered raw" section — the security note. State plainly that
`.Comment` and `.Tags` carry whatever a writer put there, that the server-side
newline collapsing applied to the built-in hosts/dnsmasq/unbound generators

template embedding those two fields into a config-file syntax is responsible for
its own escaping. Note that `text/template` does not auto-escape by design.

6. "Streaming and memory" section: state that the server sends one entry per
stream message so wire memory is bounded and the client gets gRPC flow-control
backpressure, that the client collects the whole entry set before rendering
because `.Count` and `.GeneratedAt` require it, that this collection is bounded
by a configurable cap, and — explicitly — that the server's own read of the
projection still materializes all entries in memory because the event-sourced
store has no cursor read path, so this is wire-level laziness and not
storage-level laziness.

7. "Worked example" section pointing at `examples/templates/` (created in Task 3).

<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host-entry writer to template author | `Comment` and `Tags` are attacker-influenceable by anyone with write access to the control plane and are handed to the consumer template raw |
| server-advertised contract version to client gate | The version string used for the refusal decision arrives over the mTLS stream |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-06 | Tampering | config-directive injection via `Comment`/`Tags` rendered into an unbound/dnsmasq-shaped artifact | high | mitigate | Documented as a contract property, not silently patched: `docs/reference/template-contract.md` states the fields are delivered raw, that the server-side newline collapsing in `internal/server/hostsfile.go` does not run on this path, and that escaping into the target syntax belongs to the template author — matching `text/template`'s own trusted-author security model. The three shipped examples show the intended embedding. |
| T-1-07 | Spoofing | a template silently rendering against a contract it was not written for | high | mitigate | `DeclaredVersion` refuses an undeclared template before any connection; `RequireVersion` refuses an unequal version before `Render` is called. Exact string equality only — no prefix, range, or empty-string wildcard (V5 input validation). |
| T-1-08 | Tampering | a malicious server advertising a forged contract version to coax a wrong render | low | accept | The advertised version arrives only over a CA-verified mTLS channel from the same server that holds the authoritative host data; a server able to forge it can already return arbitrary entries. No additional control. |
| T-1-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable: no package-manager install task exists in this plan and 01-RESEARCH.md's Package Legitimacy Audit records zero new external packages. |

</threat_model>
