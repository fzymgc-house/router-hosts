# Phase 1 Plan 01 — Tracer — End-to-End Consumer-Rendered Output

<objective>
Prove the whole consumer-rendered-output architecture end to end on one thin path: a
caller supplies a `text/template` file, the CLI opens a new `WatchHosts` stream, the
server streams host entries plus a snapshot terminator, and the CLI renders the
template locally and writes the artifact atomically.

This is the phase tracer. Every layer the phase will modify is touched here — proto
contract, server streaming handler, client template package, CLI command, shared
atomic-write helper — with exactly one path wired through. Every later plan expands
outward from this proven slice.

Purpose: D-01 (client-side execution) and D-03 (struct top-level value) are one-way
decisions. Proving them end to end on the first commit means an architectural
dead-end costs one plan, not ten.
Output: `WatchHosts` RPC, `internal/server/watch.go`, `internal/client/template`,
`router-hosts render` command, `internal/atomicfile`, and the change-ID derivation
(`storage.EventStore.LatestEventID`) that TMPL-08 rests on.

**Revised 2026-07-31 after cross-AI review** (`01-REVIEWS.md`). This plan absorbs
TMPL-08 (change identity, CONTEXT D-18 to D-22) into the tracer, because the change ID
is a metadata field of the D-03 contract struct and the tracer is what proves that
contract end to end. It also picks up review findings L3, L4, L7 (proto contract
comments) and L8 (bound the render drain loop from wave 1 instead of waiting for
plan 03 in wave 3).
</objective>

**TMPL-06 scope, per the amended requirement (`.planning/REQUIREMENTS.md` TMPL-06,
amended 2026-07-31 after `01-REVIEWS.md` H2):** the requirement now reads *bounded
wire messages with client backpressure*, and explicitly defers storage-layer
laziness. This phase delivers exactly that: one `HostEntry` per `stream.Send` on
`WatchHosts`, plus chunked sends on `ExportHosts`, which bounds per-message wire
memory and gives the client gRPC flow-control backpressure. It does **not** make
`store.ListAll()` a cursor read — that needs a new cursor-based
`storage.HostProjection` method and is tracked in **#400**. No plan in this phase
claims O(1) server memory; roadmap success criterion 5 was rescoped to match.

2. `internal/storage/storage.go` — add
`LatestEventID(ctx context.Context) (ulid.ULID, error)` to the `EventStore`
interface, placed after `ListAggregateIDs` and documented in that interface's
existing style: it returns the greatest `event_id` in the log, and returns the
zero ULID with a nil error when the log is empty. State in the doc comment that
this is the server's change ID (TMPL-08, D-18) and that it is a high-water mark
**only because event IDs are monotonic** — `CommandHandler` holds a
`*ulid.MonotonicEntropy` (`internal/server/commands.go:22`, built at `:32` and
`:43`) and every append mints its ID through `newID()` (`:56-61`) into
`newEnvelope` (`:77`). With bare `ulid.Make()`, two events inside one millisecond
could get suffixes ordered high-then-low, leaving the maximum pinned at the first;
the change ID would then fail to advance across a real state change and a
deduping consumer would silently keep serving a stale zone. Any future change to
ID generation must preserve monotonicity. Also declare `ZeroChangeID` in this
package as the canonical empty-store sentinel string so the server and the
compliance suite agree on one spelling (D-22).
