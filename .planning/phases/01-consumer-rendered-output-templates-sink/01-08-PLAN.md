  <precondition>The e2e suite builds and passes on this machine before any change: `task test:e2e` exits 0 on the current commit. It uses the `e2e` build tag and generates its own CA and certificates at runtime, so no external service is required.</precondition>
  <behavior>
- Over a real mTLS connection, a non-follow Watch request returns every seeded entry plus one snapshot terminator whose count matches.
- The terminator's contract version equals the version the server compiles in.
- Over a real mTLS connection, a follow Watch request receives an initial snapshot and then a further complete snapshot after a host is added through a separate RPC.
- Closing and reopening a follow stream yields a fresh complete snapshot with no resume token sent, and the entry set is identical when nothing changed in between.
- A client status message sent on a follow stream is accepted without disturbing snapshot delivery.
  </behavior>
  <action>
Extend the existing e2e suite; do not build a parallel harness. `setupTestEnv`
already produces a real CA, a real server certificate, a real client certificate
and a running server, and `dialGRPC` already returns a verified mTLS connection —
that is exactly the missing coverage.

1. `e2e/helpers_test.go` — add `collectWatchSnapshot(t *testing.T, stream grpc.BidiStreamingClient[hostsv1.WatchHostsRequest, hostsv1.WatchHostsResponse]) ([]*hostsv1.HostEntry, *hostsv1.SnapshotComplete)`
mirroring the existing `collectListHosts` shape: drain until a terminator arrives
(or the stream ends), returning the accumulated entries and the terminator. Keep
the file's existing `//go:build e2e || docker_e2e` tag intact.

2. `e2e/e2e_test.go` — add `TestE2E_WatchSnapshotOverMTLS` (seed two hosts, open a
non-follow Watch, assert the entry set and the terminator's count and contract
version), `TestE2E_WatchPushesOnMutation` (open a follow Watch, take the initial
snapshot, add a host over a second RPC on the same connection, assert a further
snapshot arrives containing it within a bounded wait), and
`TestE2E_WatchSinkReconnect` (take a snapshot, cancel the stream's context, open a
new follow stream, assert the fresh snapshot is entry-for-entry identical and that
the client sent no state to resume from). Every wait must be bounded by a context
deadline so a regression fails instead of hanging the suite.

3. In `TestE2E_WatchPushesOnMutation`, also send one `SinkStatus` upstream on the
follow stream before asserting the post-mutation snapshot, so the concurrent
send-while-receiving path is exercised over a real connection rather than only
over bufconn.

Commit as `test(e2e): cover Watch sink over real mTLS`.

The complete consumer-rendered output path: `router-hosts render` for one-shot
