<objective>
Rule out the failure mode CI-03 exists for: a gate that has never been observed
failing is indistinguishable from one that cannot fail. Apply four deliberately
chosen regressions — three tier-unique product defects plus one proving the
Docker hard-fail wire is live — on throwaway branches, watch exactly the
intended job go red in a real CI run, capture the evidence through GSD's own
verification verbs, and close every branch without merging.

Purpose: the gates built in plans 01-04 are accepted only after each has been
watched failing.

Output: four run URLs, an upstream follow-up on record, and a phase whose gates
have all been observed red at least once.
</objective>

<red_proof_protocol>
Every negative control follows the same seven steps. Deviating from them —
especially skipping the local pre-check — spends a CI run to learn something a
local command answers for free.

1. **Local tier-uniqueness pre-check (mandatory, before any push).** With the
   candidate regression applied to a dirty working tree on the phase branch,
   run `task lint`, `task test`, `task test:e2e`, `task test:e2e:docker`, and
   `task test:e2e:proc`. The candidate is ACCEPTED only if `task lint` and
   `task test` stay green AND exactly the target tier goes red AND the other
   two tiers stay green. Otherwise REJECT it and move to the next candidate.
   Record the full matrix for every candidate tried, accepted or rejected.
2. **Scratch branch.** `git switch --create rp/<tier>-<short-slug>` from the
   phase branch HEAD — the base MUST contain plan 04's `ci-go.yml`, because a
   `pull_request` event evaluates the head commit's copy of the workflow.
3. **One commit, one regression.** Commit only the regression:
   `test(e2e): TEMPORARY red proof for <tier> — DO NOT MERGE`.
4. **PR against `main`.** `gh pr create --base main --draft --title "DO NOT
   MERGE: red proof for <tier>" --body "..."`. The base MUST be `main`;
   `ci-go.yml` triggers on `pull_request: branches: [main]`, so a PR targeting
   the phase branch runs nothing. The PR's diff will include the whole phase's
   work plus the regression — that is expected and harmless. Do NOT request
   reviewers.
5. **Observe.** `gh pr checks <n> --watch`, then
   `gh run view <run-id> --json jobs --jq '.jobs[] | {name, conclusion}'`.
   Record every job's conclusion, not just the target's.
6. **Accept or reject the evidence.** Accept only if the target job's
   conclusion is `failure`; a `skipped` or `cancelled` conclusion is not a red
   proof. Confirm the other two e2e jobs and all seven pre-existing jobs
   concluded `success`, and that `CI (Go) Complete` concluded `failure`.
7. **Tear down.** `gh pr close <n>`, then delete the remote and local branch.
   Confirm with `git log --oneline main..HEAD` on the phase branch that no
   regression commit leaked into it.
</red_proof_protocol>
