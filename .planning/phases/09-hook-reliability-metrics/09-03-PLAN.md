# Phase 9 Plan 03 — Hook Outcome Classification and the Coalesced-Runs Instrument

<objective>
Make hook telemetry tell the truth about outcomes. Promote timeout to a first-class
`status` value using the context-error-first classification that the `os/exec` deadline
race demands, and add the dedicated `router_hosts_hook_runs_coalesced_total` instrument so
queue pressure is alertable without polluting the execution count.

Purpose: HOOK-01's semantic half. Plan 09-01 proved a metric can be recorded at all; this
plan makes the recorded values correct and complete, and closes the metric-shape edges
(sub-millisecond precision, duplicate names across hook types, bounded label cardinality,
declaration order).

Output: three `status` values, one new instrument wired at all eight sites, and tests that
pin the metric contract.
</objective>

**internal/server/hooks.go**

- Add unexported string constants for the three status values so no call site spells them
  as literals: one each for `success`, `failure`, and `timeout`.
- In `executeHook`, immediately after `cmd.CombinedOutput()` returns and BEFORE the
  existing `oops.Code(domain.CodeInternal).Wrapf` return, classify the outcome in this
  exact order:
  1. if `errors.Is(hookCtx.Err(), context.DeadlineExceeded)` → the timeout status;
  2. else if the process error is non-nil → the failure status;
  3. else → the success status.
  The ordering is load-bearing, not stylistic: `exec.CommandContext` kills the process when
  its context expires, and the resulting error is an ordinary `*exec.ExitError`
  indistinguishable from a hook that failed on its own merits. Inspecting the error type
  first and the context second misclassifies a hook that happened to exit non-zero in the
  same instant the deadline fired. Add `errors` to the import set.
- Record the metric with the classified status, then fall through to the existing error
  wrap unchanged, so the caller's `h.log.Error("hook failed", ...)` behavior is untouched.
- Do NOT change `router_hosts_hook_duration_seconds`: it deliberately omits the `status`
  attribute to bound cardinality and match the Rust implementation. Preserve the
  doc-comment on `RecordHookExecution` that says so.
- Do NOT pass `string(output)`, `errMsg`, or any environment value into a metric attribute.
  The counter's only variable attribute is the hook `name`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server process → hook subprocess (`sh -c`) | The hook's combined output and its exit status become inputs to the status classifier. |
| server process → OTel collector | Metric attribute values leave the trust boundary and are stored/indexed by an external system. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-06 | Information Disclosure | `RecordHookExecution` / `RecordHookRunCoalesced` attributes | low | mitigate | Attribute values are the config `name` (kebab-case ASCII, at most `MaxHookNameLength` = 50, enforced by `isValidKebabCase`) plus two closed enums. Hook stdout/stderr, `ROUTER_HOSTS_ERROR` text, and environment values are never passed to an attribute. Verified by the criterion asserting the counter datapoint's attribute key set is exactly `{name, type, status}` and the coalesced counter's is exactly `{type}`. |
| T-09-09 | Denial of Service | OTel label cardinality | low | mitigate | Series count is bounded at (configured hooks) × 2 types × 3 statuses. Because `name` comes only from validated config and never from client input, a gRPC caller cannot drive cardinality growth. |
| T-09-10 | Repudiation | outcome misclassification | medium | mitigate | Recording a deadline kill as `status="failure"` would make timeouts unattributable in incident review — the operator could not tell a hook that is too slow from a hook that is broken. Mitigated by the mandatory context-error-first ordering, with a dedicated test asserting the timeout case is NOT `failure`. |
| T-09-11 | Repudiation | telemetry overstating work | medium | mitigate | Counting a superseded (never-executed) run on `router_hosts_hook_executions_total` would make the counter lie about work performed. | T-09-04 | Tampering | `ROUTER_HOSTS_ERROR` sanitization | high | mitigate | This plan touches `executeHook` but MUST NOT restructure the four `strings.ReplaceAll` calls that strip CR/LF/NUL before `cmd.Env` is built. | T-09-SC | Tampering | package-manager installs | n/a | n/a | Not applicable — zero new dependencies in this phase. |
