  running and another run is already pending, the older pending run is DROPPED and counted
  on `router_hosts_hook_runs_coalesced_total`. Explain why this is correct rather than a
  bug: hooks react to the current contents of the output files, so a superseded run would
  only re-read the same state. Note that a persistently non-zero coalesced rate means hooks
  are slower than the write rate and is worth alerting on.
- ADD a bullet on shutdown: in-flight hooks are given the graceful-shutdown window (30s) to
  finish, after which their context is cancelled and the subprocess is killed.

  `timeout = "10s"` and a `[hooks]` table setting `default_timeout`, so the example shows
  both levels of the chain.

  attribute `type`, "Hook runs superseded before executing"), and UPDATE the
  `router_hosts_hook_executions_total` row's description to record that `status` takes
  `success`, `failure`, or `timeout` — a hook killed by its own deadline reports `timeout`
  and is deliberately not folded into `failure`.

  <action>
Extend the `[hooks]` section of `docs/reference/configuration.md`:

- ADD a `default_timeout` row to the `[hooks]` options table: type "duration string",
  default `"30s"`, described as the timeout applied to any hook that does not set its own.
- ADD a `timeout` row to the per-hook field table: type "duration string", described as
  this hook's execution timeout, with "inherits `[hooks] default_timeout`" as the stated
  behavior when omitted.
- ADD a short note directly under the field table covering three facts an operator needs:
  1. Values are Go duration strings — `"10s"`, `"2m"`, `"1m30s"` — and MUST be quoted.
  2. An UNQUOTED integer is decoded as NANOSECONDS by the TOML decoder, so `timeout = 10`
     means ten nanoseconds, not ten seconds. It is accepted (it is a positive duration) and
     will make the hook time out effectively immediately. Always quote.
  3. A negative timeout, at either level, is rejected at server start with a configuration
     error; an omitted or `"0s"` value inherits the default rather than being rejected.
  Include a short TOML snippet contrasting the correct quoted form with the footgun form,
  labelled so the wrong form is unmistakably marked as wrong.
- EXTEND the existing example hooks block with a `[hooks]` table setting `default_timeout`
  and one hook overriding it with its own `timeout`.
- State that there is no upper bound on a hook timeout, and why: hooks no longer run on the
  write path, so a slow hook cannot stall a write RPC, and an arbitrary ceiling would only
  break legitimate slow hooks. Backlog is bounded by coalescing, not by the timeout.
  </action>
