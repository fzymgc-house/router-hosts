# Phase 8 Plan 04 — Desired-Set Diff, Provenance-Gated Adoption, and Cleanup

<objective>
Complete the Service lifecycle: one desired-set diff that handles every
"stop managing this" transition through a single code path, an adoption gate that
refuses to take over another owner's DNS entry, and a `reconcileDelete` that
removes every tracked entry before releasing the finalizer.

Purpose: this is where the two destructive operations live. The stale-cleanup
pass and the delete pass both call `DeleteHost` on IDs read out of the `host-ids`
annotation, so anything that puts a foreign ID in that annotation converts a
routine reconcile into destruction of somebody else's live DNS record. The diff
and the adoption gate are the same safety property seen from two sides.
Output: a `syncService` with no early return, `addOrAdoptService` with the dual
provenance check, `hasServiceProvenance`, and a full `reconcileDelete`.
</objective>

   unreadable and proceeding would either orphan live entries or delete the wrong
   ones (D-18).
2. Build the desired set as a map from hostname to nothing more than presence —
   at most one key, because a Service carries exactly one hostname (D-06). The
   desired set is empty when any of these hold: `serviceEnabled(svc)` is false,
   the type is unsupported, the hostname is empty, or `resolveServiceIP` yields
   no usable IP. Each of those still emits its plan 02 event (or, for the
   opted-out case, no event — opting out is not an error) and still falls through
   to step 4. The `waiting` case is the one exception: a provisioning
   LoadBalancer must NOT drop its already-tracked hostname from the desired set,
   because the entry is still wanted; carry the tracked ID forward into `newIDs`
   and requeue after `requeueDelayShort`, mirroring the `noIP` branch at
   `gateway_controller.go:448-461`.
3. For a non-empty desired set, call `syncServiceHost` with the previous ID from
   `existingIDs` (or the empty string), the resolved IP, hostname, comment, the
   non-nil aliases slice, and the tags. On error, log at Error, set a `hadError`
   flag, and retain the previous ID in `newIDs` when one existed so the cleanup
   pass below does not mistake a still-desired hostname for a removed one and
   issue a spurious `DeleteHost`. A failed create has no prior ID to retain.
4. Stale-cleanup pass, always reached: for every hostname in `existingIDs` that
   is absent from `newIDs`, call `HostClient.DeleteHost` with its ID. On success
   log at Info. On failure log at Error, retain the entry in `newIDs` so it is
   not orphaned from the annotation, and set `hadError`.
5. Persist only when the map actually changed: guard `setHostIDsAnnotation` plus
   `r.Update` with `!maps.Equal(existingIDs, newIDs)` (D-19). A no-op write bumps
   the resourceVersion and re-triggers the watch for nothing.
6. Return `ctrl.Result{RequeueAfter: requeueDelayLong}` with a nil error when
   `hadError`, otherwise the zero result (D-18).

set computation, so an opted-out Service reaches step 4 and has its entry
deleted. `Reconcile` keeps the deletion-timestamp branch and the finalizer-add
branch ahead of `syncService`; do not add the finalizer to a Service that is
already opted out and tracks nothing, or a Service that merely once had the

Every fallible call stays wrapped with `oops.Wrapf`; requeues use only the

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| router-hosts server → operator (`FindHost` result) | The conflicting entry returned on `AlreadyExists` may belong to any other controller or to a CLI user; `(ip, hostname)` is not proof of ownership |
| Service `host-ids` annotation → `DeleteHost` | Any ID reaching this annotation becomes a deletion target on the next opt-out or Service delete |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | `addOrAdoptService` on `ErrHostAlreadyExists` | high | mitigate | The T-07-02 class, restated for Services. `FindHost` matches `(ip, hostname)` alone; an ungated adopt writes a foreign ID into this Service's `host-ids` annotation, after which the stale-cleanup pass and `reconcileDelete` legitimately `DeleteHost` another owner's live entry.
