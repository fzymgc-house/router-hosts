# Phase 8 Plan 02 — IP Resolution Matrix, Failure Events, and the Events RBAC Fix

<objective>
Expand the tracer's LoadBalancer-only IP resolution into the full locked matrix
(LoadBalancer / NodePort / annotation override / unsupported types), make every
operator-visible failure and waiting state emit the Kubernetes Event reason the
Rust-era design specified, and close the confirmed cluster-scoped `events` RBAC
gap that would otherwise make all of it silently invisible in a real cluster.

Purpose: three of the four reasons are decided by IP resolution, so the matrix
and the events are one concern. The RBAC fix ships in this plan — not a later
one — because an `Eventf` call without the rule is a no-op the `FakeRecorder`
cannot detect.
Output: a complete `resolveServiceIP`; four nil-guarded `Eventf` call sites with
terminal-vs-requeue semantics; kubebuilder RBAC markers; and a ClusterRole that
grants `services` and cluster-scoped `events`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Kubernetes API server → operator | `Service.Status.LoadBalancer.Ingress` and the `ip-address` annotation are both attacker-influencable inputs that become the published DNS address |
| operator → Kubernetes API server (events) | The operator writes Event objects cluster-wide on behalf of its ServiceAccount |
| Helm chart → cluster RBAC | The rendered ClusterRole is the authorization boundary for everything above |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-04 | Repudiation | `events.EventRecorder.Eventf` without a cluster-scoped `events` rule | high | mitigate | `Eventf` has no error return and the recorder swallows write failures by design, so a denied event is invisible — a security-relevant signal that never reaches anyone. Task 1 confirms the gap empirically, adds `apiGroups: [""] resources: ["events"] verbs: ["create","patch"]` to the ClusterRole, and verifies the rendered `verbs:` line contains both verbs. Fixes `HostMappingReconciler`'s pre-existing silent failure as a side effect. |
| T-08-05 | Elevation of Privilege | cluster-wide `update`/`patch` on `services` | medium | mitigate | The grant is inherent to writing the finalizer and `host-ids` annotation back, and matches the shape already granted for IngressRoutes and Gateway routes. Least privilege is enforced by scoping: no `delete`, no Service status subresource. Task 1 asserts the rendered verbs line is exactly the five allowed verbs, so a widening is a test failure rather than a review miss. |
