# Phase 8 Plan 01 — Tracer: One LoadBalancer Service Becomes One Router DNS Entry

<objective>
Prove the whole Service path end to end on one thin slice: a single
`LoadBalancer` Service that opts in via annotation and reports one non-empty
`status.loadBalancer.ingress[].ip` becomes one router DNS entry — with the
opt-in/opt-out predicate, the `service-cleanup` finalizer, and the `host-ids`
annotation lifecycle already in place, behind `--enable-service`.

watch predicate that must stay symmetric across Update, and (b) the typed
`corev1.Service` reconcile path reading `status` and writing metadata back.

full type/IP matrix, the four Events, alias handling, and the diff/cleanup
lifecycle.
Output: `internal/operator/service_controller.go` with a working LoadBalancer
happy path and a correct D-05 predicate; `internal/operator/service_controller_test.go`;
`cmd/operator/main.go` wired behind `--enable-service`.

  <context>
This is a one-way door. The next task writes this exact string onto every Service
the operator reconciles. Once a release carrying it reaches a user cluster, live
Service objects hold that finalizer. Renaming it afterwards migrates nothing: the
old finalizer stays on every existing Service, no controller recognises it, and
Kubernetes blocks deletion of those Services until a human patches each one by
hand. There is no automated undo, and a Service is a far more commonly deleted
object than a HostMapping or an IngressRoute, so the blast radius of a strand is
larger than the three finalizers already shipped.

The proposed name is the fourth in an established series — `.../host-cleanup`
(hostmapping_controller.go:27), `.../ingressroute-cleanup`
(ingressroute_controller.go:29), and `.../gateway-cleanup` (gateway_controller.go,
confirmed at the Phase 7 plan checkpoint) — and is deliberately distinct from all
three so the four controllers never contend for the same finalizer.

|----------|-------------|
| Kubernetes API server → operator | Service objects are attacker-influencable by anyone with annotate/update rights on a Service in any namespace |
| operator → Kubernetes API server (write) | The operator writes finalizers and the `host-ids` annotation back onto Services cluster-wide |
| operator → router-hosts gRPC server | Host mutations cross an mTLS boundary into the authoritative DNS store |
