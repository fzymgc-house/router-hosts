# Phase 8 Plan 03 — Hostname Validation, Aliases, and the Per-Host Sync Path

<objective>
Turn the tracer's raw annotation read into the real desired-entry contract:
a validated hostname with the project-consistent non-FQDN warning, a validated
comma-separated alias list mapped onto the host entry's native `Aliases` field,
and a per-host sync path that refreshes an already-tracked entry safely.

Purpose: this phase is the first operator-side consumer of the `aliases`
parameter that has existed on `HostClient` since Phase 1. That parameter has
nil-versus-empty semantics no existing controller has ever exercised, and getting
it wrong leaks stale aliases into router DNS silently and permanently.
Output: `serviceDesiredHostname`, `serviceDesiredAliases`, and
`(*ServiceReconciler).syncServiceHost` with the read-before-write fail-closed
guard.
</objective>

Add `func serviceDesiredAliases(log *slog.Logger, svc *corev1.Service, canonicalHostname string) []string`
to `internal/operator/service_controller.go`.

Initialize the result as `make([]string, 0, ...)` — never `var aliases []string`.
The zero value of a Go slice is nil, and `grpcHostClient.UpdateHost`
(`internal/operator/grpc_hostclient.go:131-133`) only attaches the wire-level
aliases update when the slice is non-nil, so a nil result silently means "leave
the server's aliases alone" instead of "clear them". A Service whose aliases were
removed would then keep publishing them forever. This function must return a
non-nil slice on every path, including the annotation-absent path.

Read the `aliases` annotation, `strings.Split` it on commas,
`strings.TrimSpace` each segment, and skip empty segments (so a trailing comma
is harmless). Validate each surviving segment by calling
`validation.ValidateAliases([]string{alias}, canonicalHostname)` and treating a
non-empty error slice as "drop this one": log at Warn naming the alias and the
first error, then continue to the next segment. Calling the existing validator
per-alias is what gives you the IP-address rejection, the canonical-hostname
match rule, and hostname validity without hand-rolling any of them. Deduplicate
case-insensitively across the accumulated result yourself (the per-alias call
cannot see the others), logging a Warn for each dropped duplicate. An invalid or
duplicate alias is never fatal — the canonical hostname's entry is still created
(D-07).

Do NOT read any user-supplied `tags` annotation (D-22). Entry tags stay
operator-derived provenance (`DefaultTags` plus the literal `service`), because
plan 04's ownership check reads them; mixing user-controlled values in would

about. Adding a user tags annotation later is a small additive change that needs
its own ownership analysis.

Reuse the package-level `recordingHandler` from `gateway_controller_test.go` for
the Warn assertions; do not declare a second one.

  <action>
Add `func (r *ServiceReconciler) syncServiceHost(ctx context.Context, log *slog.Logger, prevID, ip, hostname, comment string, aliases, tags []string) (string, error)`
to `internal/operator/service_controller.go`, modelled on
`ingressroute_controller.go:216-253`.

When `prevID` is empty, delegate straight to `addOrAdoptService`.

When `prevID` is non-empty, read the current entry with
`r.HostClient.GetHost(ctx, prevID)` first and branch on the result:

- read succeeded with a non-nil entry: call
  `r.HostClient.UpdateHost(ctx, prevID, ip, hostname, comment, aliases, tags, current.Version)`
  **unconditionally** — do not add an "already in sync" early return. D-19 keeps
  the update unconditional so a changed LoadBalancer IP or a changed alias set
  propagates without this controller keeping any last-known state; the read
  exists to supply the optimistic-concurrency version and to fail closed, not to
  skip the write. If that call returns `ErrHostNotFound` the entry vanished
  between read and write: log at Warn and fall through to recreate via
  `addOrAdoptService`. Any other error is wrapped with `oops.Wrapf` and returned
  alongside `prevID` so the caller retains the ID.
- read returned `ErrHostNotFound`: the entry was deleted out of band; log at Warn
  and recreate via `addOrAdoptService`. The Service is the source of truth.
- read returned a nil error and a nil entry: fail closed with an `oops.Errorf`
  naming the ID. Neither an entry nor an error does not justify a
  delete-and-recreate.
- any other read error: fail closed, returning `prevID` and the wrapped error.
  Without current state you can neither pick a safe version nor avoid
  re-appending events (#338).

Change `addOrAdoptService` and the `syncService` create path to accept and pass
the aliases slice from `serviceDesiredAliases` rather than nil, and route the
tracked-hostname case in `syncService` through `syncServiceHost`. The aliases
argument must be the non-nil slice task 2 produces on every path — passing nil is
what leaves stale aliases published forever.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Service annotations → validation layer | `hostname` and `aliases` are free-form untrusted strings supplied by whoever can annotate the Service |
| operator → router-hosts gRPC server | Validated hostname and aliases become authoritative DNS records |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-14 | Tampering | `serviceDesiredHostname` / `serviceDesiredAliases` input validation | medium | mitigate | Every hostname goes through `validation.ValidateHostname` and every alias through `validation.ValidateAliases`, which rejects raw IPs, malformed hostnames, aliases equal to the canonical name, and over-long lists. Both validators are shipped, property-tested code reused rather than rebuilt (ASVS V5). An invalid value is dropped with a Warn, never published. |
| T-08-15 | Tampering | stale aliases persisting after the annotation is cleared | medium | mitigate | `grpcHostClient.UpdateHost` treats a nil slice as "leave untouched", so a nil alias slice silently keeps a removed alias resolving indefinitely — a DNS record the Service owner believes they deleted. `serviceDesiredAliases` returns a non-nil slice on every path and `TestSyncService_AliasesClearedSendsEmptySlice` asserts `NotNil` plus `Empty` on the captured argument. |
| T-08-16 | Tampering | blind `UpdateHost` without a prior read | medium | mitigate | `syncServiceHost` fails closed on any non-NotFound read error and passes the read's version string as the optimistic-concurrency token, so a concurrent writer's change is not silently clobbered and no event is re-appended (#338). |
| T-08-07 | Spoofing | non-FQDN hostname → pseudo-TLD authority under ADR `router-hosts-bzg` | low | accept | Carried forward from plan 01. D-08 accepts a dot-less name with a Warn for cross-controller consistency; task 1's `dotless_accepted_with_warning` case pins both halves so the acceptance stays deliberate and visible rather than silent. |
| T-08-17 | Elevation of Privilege | user-controlled values entering the provenance tag set | high | mitigate | Plan 04's ownership check reads the entry tags, so a user-supplied `tags` annotation would let a Service owner forge another controller's provenance and cross-delete its entries. D-22 defers the annotation entirely for this phase; task 2 asserts the annotation key appears nowhere in the controller. |
