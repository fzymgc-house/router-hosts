# Phase 7 Plan 03 — IP Resolution from the Parent Gateway

<objective>
Make IP resolution from the parent Gateway complete and total: every ordering,
skip, defaulting, fallback, and failure path in D-15 and D-16 is implemented and
proven, and no route can ever produce an IP-less DNS entry.

Purpose: GW-02 is exactly this behavior, and the failure mode it guards against —
an entry written with an empty or wrong IP — is silent at write time and only
visible later as broken DNS.
Output: a complete `resolveIP`, and a `syncRoute` that requeues rather than
writing when no IP can be resolved.
</objective>

in `internal/operator/gateway_controller.go` per D-15.

Iterate `parentRefsOf(obj)` in declaration order — that ordering is the tie-break
contract, so do not sort, filter, or reorder the slice. For each ref: compute the
parent namespace as `obj.GetNamespace()` when `ref.Namespace` is nil, otherwise
`string(*ref.Namespace)`; `Get` a `gatewayv1.Gateway` at

a CNAME target or an opaque implementation-specific name is not a host entry IP.

returning. When the whole walk yields nothing, return `r.DefaultIP` (task 2
handles what happens when that is also empty).

no goroutines, no caching between calls. It is called once per `syncRoute` and
reads through the reconciler's own `client.Client`, so the informer cache in
production and the fake client in tests exercise the identical path.

  <action>
Finish the D-16 half of IP resolution in `internal/operator/gateway_controller.go`.

In `resolveIP`: when a parent Gateway `Get` fails, inspect the error. A
`apierrors.IsNotFound` failure is an ordinary "parent not created yet" condition —
continue to the next parentRef without logging at error level. Any other failure
is logged with `log.Error` naming the `<namespace>/<name>` of the Gateway and the
error, and the walk still continues to the next parentRef. Never return early on a
`Get` failure and never propagate it: `resolveIP` returns a string, and an
unreachable parent must not fail the whole reconcile when a later parent or the
flag can still supply an IP.

In `syncRoute`: after computing `ip := r.resolveIP(...)`, when `ip` is the empty
string, emit `log.Warn` naming the route and return
`ctrl.Result{RequeueAfter: requeueDelayShort}` with a nil error — before any
`HostClient` call, before reading or writing the `host-ids` annotation. An entry
with no IP is never created; the reconcile retries instead. Use the existing
package-level `requeueDelayShort` from `hostmapping_controller.go`; do not
redeclare it and do not introduce a new delay constant.

Wrap nothing that is not fallible; `oops.Wrapf` still guards every genuinely
fallible call in this path per D-14. No `log.Fatal` and no `os.Exit`.

<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Kubernetes API server → operator | `Gateway.status.addresses` is written by the cluster's Gateway controller, not by this operator; a principal who can create a Gateway (or whose Gateway controller is compromised) controls the IP this operator publishes |
| Namespace A route → namespace B Gateway | `parentRefs` may name a Gateway in another namespace, which the operator reads directly |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-05 | Information Disclosure | `resolveIP` cross-namespace `Gateway` Get | low | accept | A route in namespace A can reference a Gateway in namespace B without a `ReferenceGrant`, surfacing that Gateway's `status.addresses` value into a DNS entry. Explicitly out of scope per CONTEXT § Deferred Ideas ("ReferenceGrant enforcement for cross-namespace parentRefs"); the operator performs a read-only `Get` and is not acting as the Gateway controller. Not a regression — carried over unchanged from the design doc's Risks section. Do not add enforcement without a new CONTEXT decision. |
| T-07-08 | Spoofing | `Gateway.status.addresses` as the IP source | medium | accept | Whoever controls the parent Gateway's status controls where the published hostname points. That is inherent to GW-02 as written — the requirement is to resolve IPs from the parent Gateway's status. Cluster RBAC on `gateways/status` is the control, and it lives outside this operator. |
| T-07-12 | Denial of Service | `syncRoute` with an unresolvable IP | medium | mitigate | The reconcile returns `RequeueAfter: requeueDelayShort` with a nil error rather than writing an IP-less entry or hot-looping on an immediate requeue, so a permanently unresolvable route costs one lookup per 5 seconds and never corrupts the DNS output. |

</threat_model>
