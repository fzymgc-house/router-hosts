# Phase 1 Plan 08 — Real-mTLS E2E, Operator Guide, and Phase Verification

<objective>
Close the phase: prove the whole path over real mTLS, write the operator-facing guide,
and run the manual verifications the automated suite structurally cannot cover.

Purpose: every plan before this one verified through bufconn with insecure
credentials, which means the mTLS common-name extraction feeding D-09/D-13 has never
actually run against a verified certificate chain. That gap closes here.
Output: an e2e Watch round trip, a consumer-rendered-output guide, CLI reference
entries, and a signed-off manual verification record.

**Revised 2026-07-31 after cross-AI review** (`01-REVIEWS.md`).

**M3 — the pre-review plan asserted the sink-identity claim without validating it.**
The e2e harness builds the service without `WithSinkHealth`
(`e2e/helpers_test.go:103`), so sending a status message over a real connection
proved neither that the CN was extracted nor that anything was keyed by it. The
harness now injects the registry and the test asserts the literal
`e2e-test-client` (`helpers_test.go:222`).

**M4 — "connection interruption" meant cancelling one RPC on a live
`grpc.ClientConn`.** That exercises stream restart, and nothing else: not TCP or TLS
interruption, not keepalive detection, not redial, and not the CLI reconnect
supervisor plan 07 builds. Since the harness creates its own listener on a known
address, the server can genuinely be stopped and restarted underneath a running
`router-hosts watch`, which is what the phase criterion actually claims.

Also picks up pi's suggestion 6 (assert the failure count resets after reconnect)
and adds TMPL-08 coverage over a real connection.

**Revised 2026-08-01 after cross-AI review round 2** (`01-REVIEWS.md` H4, H6, M10, L4,
L10, M6). The round-1 restart test **would not have compiled**, and the helper it
depended on was underspecified.

**H4 — the test could not reach what it planned to set.** `e2e/helpers_test.go:3`
declares `package e2e_test`, an external test package, so unexported package-level
variables in `internal/client/commands` are invisible to it. The round-1 plan said to
"set the package-level backoff variables in `internal/client/commands` to
milliseconds", which does not build. Plan 07 now exports a `WatchPolicy` value and a
`NewRootCmd(WithWatchPolicy(...))` option instead of mutable globals, and this plan
uses that seam. Codex's framing is worth keeping: do not expose mutable production
globals merely for e2e — inject a policy.

**H6 — `testEnv` does not hold enough to restart anything.** The struct
(`helpers_test.go:33-47`) carries `srv`, `cancel`, `conn`, `tmpDir` and cert paths,
while `srvErrCh` is a **local** in `setupTestEnv` (`:112`) that the cleanup closure
captures. A restart must replace the server pointer, the cancel function and the error
channel on every start; adding only `addr` and `sinkHealth`, as round 1 proposed, is
not enough, and reusing a stale cancel or waiting on a consumed channel produces a
hang rather than a failure.

**M10 — a `restartServer` that stops and immediately waits for readiness leaves no
outage to observe.** The test text says "call `restartServer`; while the server is
down, assert...", which cannot happen if the helper returns healthy. Split into
`stopServer` and `startServer`.

**L4, L10, M6 — three smaller items.** Re-listening on the same address can transiently
fail, so `startServer` gets one bounded retry rather than a hard `require.NoError`
(L4). The harness sets `MinVersion: tls.VersionTLS12` (`helpers_test.go:258`) while
production client credentials require TLS 1.3 (`internal/client/client.go:82`), so a
direct harness connection tests a weaker policy than the real client — aligned to 1.3
(L10). And the guide gains the unique-CN deployment requirement (M6).

## Revised 2026-08-01 after cross-AI review round 3 (`01-REVIEWS.md` H5, M6)

**H5 — round-2's H6 fix was accepted on a change that does not make `startServer`
implementable.** Adding `addr`, `sinkHealth`, `srvErrCh` and `running` to `testEnv`
addresses the *lifecycle* state but not the *construction* inputs. Verified against the
current harness: `store` is a local at `e2e/helpers_test.go:69`, `cfg` is a local at
`:79`, and `handler`, `svc` and the listener are locals around `:101-104`. None of them
is retained anywhere. `startServer(t, env)` as specified cannot build
`server.NewServer(cfg, store, logger, server.WithListener(lis))` or call
`hostsv1.RegisterHostsServiceServer(srv.GRPCServer(), svc)` because it has no `cfg`, no
`store`, no `logger` and no way to construct the service over the same store. Same class
as round-2 H6, only partially fixed. Task 1 now specifies exactly which inputs are
retained, and offers the closure alternative Codex suggested.

**M6 — reusing `env.client` after a restart needs a stated contract.** The
`grpc.ClientConn` is created once at `helpers_test.go:120` and stored on `testEnv`.
gRPC will reconnect to the same address on its own, but a helper call issued
immediately after `startServer` can land during `TRANSIENT_FAILURE` backoff and fail
for a reason that has nothing to do with what the test is asserting. **Decision:
redial and replace `env.conn` and `env.client` on every start**, closing the previous
conn, rather than relying on transparent reconnect with bounded contexts. It is the
simpler contract to reason about, it makes each start produce a connection whose state
is known, and the restart test's own assertion about the real `router-hosts watch`
supervisor — which does exercise transparent reconnect — is unaffected because that
process holds its own connection.

1. `e2e/helpers_test.go` — three changes. Keep the file's existing
`//go:build e2e || docker_e2e` tag intact.

   a. **Wire sink health (review M3).** At the `server.NewHostsServiceImpl(handler, store)`
   call (:103), construct `sinkHealth := server.NewSinkHealth()` and pass
   `server.WithSinkHealth(sinkHealth)`. Add `sinkHealth *server.SinkHealth` and
   `addr string` fields to the `testEnv` struct and populate both. Without this
   the CN-keying claim cannot be checked at all: the harness currently builds the
   service with no registry, so a status message is accepted and discarded, and a
   test asserting "identity is keyed by CN" would pass whether or not extraction
   works.

   b. Add `collectWatchSnapshot(t *testing.T, stream grpc.BidiStreamingClient[hostsv1.WatchHostsRequest, hostsv1.WatchHostsResponse]) ([]*hostsv1.HostEntry, *hostsv1.SnapshotComplete)`
   mirroring the existing `collectListHosts` shape: drain until a terminator
   arrives (or the stream ends), returning the accumulated entries and the
   terminator.

   c. **Split the lifecycle into `stopServer` and `startServer`** (reviews M4, M10,
   H6, L4). A single `restartServer` that stops and then waits for readiness leaves
   no externally observable outage, so the test cannot assert anything "while the
   server is down" — which is the whole point of the M4 scenario.

   First move the per-start state onto `testEnv`, because there is not enough there
   today (review H6). `srvErrCh` is currently a **local** in `setupTestEnv` (`:112`)
   captured by the cleanup closure, and `srv` and `cancel` (`:33-47`) are written once
   at construction. Add `addr string`, `sinkHealth *server.SinkHealth`,
   `srvErrCh chan error` and `running bool` to the struct, and have `startServer`
   replace `srv`, `cancel` and `srvErrCh` on **every** call. Reusing a consumed error
   channel or a stale cancel function produces a hang on the second stop rather than
   a test failure, which is the worst failure mode available in an e2e suite.

   **Retain the CONSTRUCTION inputs too, or `startServer` cannot be written at all
   (review round-3 H5).** Lifecycle state is not enough. Right now `store` is a local at
   `:69`, `cfg` is a local at `:79`, and `handler`, `svc` and the listener are locals
   around `:101-104` — so nothing on `testEnv` lets a second server be built over the
   **same** store. Add `store *sqlite.Storage`, `cfg config.Config` and
   `logger *slog.Logger` to the struct alongside the lifecycle fields. Both the store
   and the sink-health registry must be the *same instances* across a restart: the store
   because the whole point of the test is that data survives, and the registry because
   the CN test reads it after the restart. Build the `CommandHandler` and the service
   fresh inside `startServer` from those retained inputs — a new `HostsServiceImpl` over
   the same store is correct and is what a real server restart does.

   If you prefer Codex's alternative, it is equally acceptable and may read better:
   store a `newServer func(net.Listener) (*server.Server, error)` closure on `testEnv`
   that captures `store`, `cfg`, `logger` and `sinkHealth` at setup time and does the
   build-and-register in one place. Choose one shape and use it consistently; do not
   half-retain the inputs and reconstruct the rest ad hoc, which is exactly how the
   round-2 revision passed review while remaining unimplementable.

   `stopServer(t *testing.T, env *testEnv)`: return immediately if `env.running` is
   false, so it is idempotent. Otherwise call `env.cancel()`, wait for `env.srvErrCh`
   with the same bounded `select` the cleanup block at `:137-147` uses, set
   `env.running = false`, and return. Do **not** wait for readiness. Close `env.conn`
   here and set `env.conn` and `env.client` to nil, so a helper call made against a
   stopped server fails loudly rather than blocking in reconnect backoff (review M6).

   `startServer(t *testing.T, env *testEnv)`: `net.Listen("tcp", env.addr)` on the
   **same address**, build a fresh `server.NewServer(env.cfg, env.store, env.logger, server.WithListener(lis))`,
   construct a fresh `server.NewCommandHandler(env.store)` and
   `server.NewHostsServiceImpl(handler, env.store, server.WithSinkHealth(env.sinkHealth))`
   over the retained store and the retained registry, register the service on the new
   `srv.GRPCServer()`, assign the new `srv`, `cancel` and `srvErrCh` onto `env`, run it
   in a goroutine, call the existing `waitForServer`, then **redial and replace
   `env.conn` and `env.client`** with `dialGRPC(...)` (review M6), and finally set
   `env.running = true`. Redialing per start is the decided contract: it makes the
   connection state after every start known, instead of leaving helper calls to race
   gRPC's transparent-reconnect backoff. Note in a comment that this is a harness
   choice and says nothing about production clients — the real `router-hosts watch`
   under test holds its own connection and is deliberately left to reconnect on its own,
   which is the behavior `TestE2E_WatchSinkSurvivesServerRestart` exists to exercise.

   Give the `net.Listen` call one bounded retry rather than a hard `require.NoError`
   (review L4): rebinding an address whose previous connections may still be in
   TIME_WAIT can transiently fail on some platforms, and a hard assertion turns that
   into an intermittent red suite. Retry a small number of times with a short sleep,
   then fail with a message naming the address.

   Refactor `setupTestEnv` so it populates `addr`, `sinkHealth`, `store`, `cfg` and
   `logger` (or the `newServer` closure) and then calls `startServer`, rather than

   cleanup is correct whether a test left the server running or stopped; since

   so this should be a no-op that closes the divergence rather than a behavior change.
   If any existing test breaks, stop and report it rather than reverting the minimum:
   a harness that only passes at TLS 1.2 would mean the server is not actually
   1.3-capable, which is a finding, not a test problem.

     `e2e` is `package e2e_test`, so the unexported package variables the round-1

     `SetArgs` with
     `watch --server <addr> --cert ... --key ... --ca ... --template ... --out ...
     --status-file ...`, and run `ExecuteContext(ctx)` in a goroutine with a
     cancellable context.

     Then, using the split lifecycle so the outage is real and observable
     (review M10):
     1. Wait for the artifact to appear and record its bytes.
     2. Call `stopServer(t, env)` and return — the server is now down and stays down.

     5. Wait with a bound for the sink to rewrite, assert the artifact now contains
        the new host, and assert `consecutive_failures` is back to zero
        (pi suggestion 6).
     6. Cancel the context and assert the command returns.
