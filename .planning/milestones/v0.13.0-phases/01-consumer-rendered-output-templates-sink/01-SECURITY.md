# Phase 01 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

Retroactive verification run for a phase whose threat register was authored at
plan time. All 11 plans carried a `<threat_model>` block, so
`register_authored_at_plan_time: true` — this audit verifies that each declared
mitigation is present in the implementation, and does not scan for new threats.

---

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `--exec` command string to the local shell | An operator-supplied string is executed by `sh -c` with the sink process's privileges |
| `--out` and `--status-file` paths to the filesystem | Two operator-supplied paths are written on every successful cycle |
| `EventStore` interface to arbitrary callers | The append methods accept caller-constructed envelopes, so the ID they carry is untrusted input to the ordering invariant |
| ambient environment (XDG dirs, env vars) to config resolution | Files the invoking command never named can influence, or before this fix entirely determine, the connection target |
| client CLI to server (mTLS gRPC) | Every `WatchHosts` caller is CA-verified (`tls.RequireAndVerifyClientCert`, `internal/server/server.go:207`); the request body itself is untrusted input |
| client keepalive behavior to server resources | A misconfigured client pinging aggressively consumes server resources |
| client to gRPC server (mTLS) | The resolved config decides which endpoint is dialed and which client certificate and CA are presented; both are attacker-relevant if mis-resolved |
| compaction (storage layer) to the event log's ordering invariant | Compaction deletes and reinserts events without passing through the command layer |
| consumer status message to server state | Untrusted request-body content updates a per-consumer record |
| consumer status report to server state | Values a consumer reports about its own health are stored server-side |
| consumer stream to server goroutines | Each connected sink causes the server to hold a goroutine, a subscription and a periodic full read of the projection |
| documentation to operator action | The guide tells an operator to run a shell command as a post-write hook |
| environment and config file to limit value | The ceiling protecting client memory is itself operator-supplied input |
| event append path to the change-ID derivation | Every write, from any caller, contributes the value the change ID is read from |
| generated test PKI to loopback mTLS | A CA, a server leaf, and per-CN client leaves are minted per test run and live only in the test's temp directory |
| host-entry writer to template author | `Comment` and `Tags` are attacker-influenceable by anyone with write access to the control plane and are handed to the consumer template raw |
| legacy Rust-era migration to the events table | `legacy_migration.go:183` inserts preserved external IDs directly, outside the guarded funnel, bounded only by running before seeding and skipping on a non-empty table |
| mTLS peer certificate to metric label | The only identity permitted to become a metric label value crosses here |
| operator intent to resolved client config | The operator names a target server and a credential set; a defect here substitutes a different, unnamed target and credential set with no signal |
| operator-supplied template file to `text/template` | Template source is read from a local path and executed in the CLI process |
| process lifetime to persisted log | A restarted process starts with a generator that knows nothing about rows already on disk |
| real client certificate to server-side identity | This is the first plan where the common-name extraction runs against an actually verified chain |
| server stream framing to client memory | Message size on the wire is entirely under server control |
| server stream to client memory | Every response message the client accumulates is attacker-controllable in volume by a compromised or buggy server |
| server stream to local artifact file | Server-supplied data becomes a file a resolver daemon parses and acts on |
| server to consumer artifact file | Rendered bytes cross into a file that a resolver daemon will read and act on |
| server-advertised contract version to client gate | The version string used for the refusal decision arrives over the mTLS stream |
| test process to child router-hosts processes | Environment, arguments, and config files are the entire interface; anything inherited implicitly is an unverified assumption |

| T-1-16 | Denial of Service | metric-storage exhaustion via unbounded label cardinality | high | mitigate | Claim restated after review M6, which found the original "bounded by construction" too strong. What is bounded: label **values** come only from CA-issued mTLS common names (D-13), never from caller-supplied text, and `MaxTrackedSinks` caps the registry at 1000 entries with oldest-last-seen eviction, so the server exports at most 1000 per-identity series at any one time. What is **not** bounded: the number of distinct label values a backend has observed over the process's lifetime — an evicted CN that reconnects reappears, and the backend retains both. The mitigation therefore rests on the label source being an issuing-CA decision, not on the eviction ceiling. Separately, the change ID is deliberately reduced to a 0/1 convergence gauge rather than emitted as a label, because a value that changes on every mutation would be unbounded by construction; and the render-failure counter that bypassed the registry entirely has been removed (review M5). | closed |

| T-1-23 | Denial of Service | concurrent `Send` from two goroutines corrupting the stream | high | mitigate | Exactly two goroutines are spawned: one is the sole owner of `stream.Send`, the other the sole owner of `stream.Recv`, and the handler goroutine touches neither. This matches the grpc-go concurrency contract — which forbids two senders or two receivers, not a handler that owns nothing — and is asserted by a goroutine-count criterion plus repeated race-detector runs. | closed |
