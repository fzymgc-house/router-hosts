## Outcomes

**HOOK-01 — validated as written.** The requirement named the defect precisely
("currently dead code"). The fix was a wiring change plus a regression guard, not
new metric design: the existing `router_hosts_hook_executions_total` and
`router_hosts_hook_duration_seconds` instruments were reused unchanged, matching
the Rust implementation's label sets.

**HOOK-01 — one deliberate extension.** `status="timeout"` was added as a third
value alongside `success`/`failure`, a conscious divergence from strict Rust label
parity, because HOOK-02 promotes timeout to a first-class outcome. A separate
`router_hosts_hook_runs_coalesced_total` instrument was added rather than a
`status="skipped"` value, to keep `executions_total` a truthful execution count.

**HOOK-02 — adjusted during discussion, not during execution.** The requirement
said "bounded concurrency model". The locked design chose *sequential within a
batch* (post-edit hooks are order-dependent: write, then reload) with bounding
applied to in-flight *batches* instead — queue depth 1 with coalescing. Parallel
hook execution was explicitly rejected and recorded as a deferred idea.

**HOOK-02 — a contradiction surfaced and was resolved.** CONTEXT specified the
timeout "must be > 0"; research found that 0 should mean "inherit the default".
Reconciled by splitting the check: `HookDefinition.validate()` rejects only `< 0`
(the existing test table calls it directly on zero-valued definitions), while
`resolveTimeouts()` — the only code that has walked the full chain — enforces
strict `> 0`.

## Deferred

Recorded as deferred rather than satisfied. Neither blocks the milestone.

- **Live OTel/Prometheus scrape** — never run; no collector available in the
  execution session. Instrument registration and recording call sites are proven
  by unit tests; end-to-end export is unexercised.
- **Exact-instant coalescing interleaving** — accepted backstop, closed by a
  documented mutex-ordering argument rather than a direct test.
