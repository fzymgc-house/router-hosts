# Phase 9 Plan 04 — Hook Runner Coalescing, Conservation, and Bounded Shutdown

<objective>
Harden the runner Plan 09-01 introduced: make coalescing accountable, make shutdown
bounded and provably terminating, and prove the conservation law that no trigger is
silently lost.

Purpose: HOOK-02's reliability half, and the mitigation for the phase's only
high-severity threat (unbounded pending-work growth under write churn). Plan 09-01 built
the pending slot; this plan instruments it, drains it correctly on shutdown, and proves
the semantics with deterministic sentinel-based tests.

Output: a runner whose backlog is bounded at one, whose shutdown always terminates, and
whose coalesced runs are visible on `router_hosts_hook_runs_coalesced_total`.
</objective>

**internal/server/hookrunner.go**

- In `loop`'s `quit` branch, before returning: take the mutex, take `pending`, set it to
  nil, release, and run it if non-nil. This is the direct analogue of
  `WriteQueue.process`'s drain-the-buffer step, bounded here at a single request because
  the slot holds at most one. Return after that single drain — do not loop.
- In `Stop(ctx)`, keep the `WriteQueue.Stop` mutex-guarded shape: under the mutex, if the
  stopped flag is not yet set, set it and `close(r.quit)`; a second call must fall through
  without closing an already-closed channel. Then
  `select { case <-r.done: case <-ctx.Done(): r.cancel(); <-r.done }`. The post-cancel
  `<-r.done` wait is mandatory: without it Stop can return while the goroutine is still
  unwinding, which is exactly the leak the bounded drain is supposed to prevent.
- In `Trigger`, read the stopped flag under the mutex and return immediately when set.
  A post-Stop trigger must not park a request nobody will ever drain and must not record
  a coalesce.
- Ensure `r.cancel` is always eventually called so the base context is not leaked — call
  it after the `done` wait in `Stop` as well, so the normal (in-deadline) path releases it
  too.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gRPC client → write RPC → hook runner | Client-driven write rate reaches the runner as `Trigger` calls; the pending slot is the only place that rate could accumulate memory or work. |
| server process → hook subprocess (`sh -c`) | A detached hook now outlives the RPC that caused it and must be terminable at shutdown. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-02 | Denial of Service | `internal/server/hookrunner.go` — pending request slot | high | mitigate | Queue depth is exactly one by construction: `Trigger` OVERWRITES `pending` instead of appending, and the `trigger` channel has capacity 1 with a non-blocking send. In-memory pending work is bounded at one request plus one in-flight batch regardless of write-RPC rate. Verified by source criteria (single pointer field, capacity-1 channel) and by the 50-concurrent-trigger conservation test, which shows 50 triggers collapse into a bounded number of executions. |
| T-09-03 | Denial of Service | `Stop(ctx)` bounded drain | medium | mitigate | `Stop` waits on `done` up to the caller's deadline, then cancels the runner's base context, which `exec.CommandContext` uses to kill the hook subprocess, and only then returns after a second `done` wait. `TestHookRunner_StopDrainsThenCancels` proves Stop terminates against a hook that blocks forever and that the hook never completes. |
| T-09-12 | Denial of Service | post-Stop `Trigger` | low | mitigate | A `Trigger` after `Stop` returns early under the stopped flag, so it cannot park a request that nobody will drain and cannot leak an unreferenced `hookRunRequest`. Verified by `TestHookRunner_TriggerAfterStopIsNoOp`. |
| T-09-05 | Elevation of Privilege | detached hook vs. RPC auth context | low | accept | A hook that outlives its RPC gains nothing: hook commands are operator-authored config, and `runBatch` passes only the runner's own base context plus plain data (`event`, `entryCount`, `errMsg`). No caller identity, credential, or authorization decision was ever available to a hook, so detaching removes a lifetime coupling without transferring any privilege. Accepted with rationale. |
| T-09-11 | Repudiation | telemetry honesty | medium | mitigate | Superseded runs increment `router_hosts_hook_runs_coalesced_total`, never `router_hosts_hook_executions_total`, keeping the execution counter a truthful count of commands actually run. Verified by the conservation assertions. |
| T-09-SC | Tampering | package-manager installs | n/a | n/a | Not applicable — zero new dependencies in this phase. |

Blocking threshold `high`: T-09-02 is the only `high` entry and is dispositioned
`mitigate` with both source-level and behavioral verification.
