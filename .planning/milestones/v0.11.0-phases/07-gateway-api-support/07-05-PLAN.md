# Phase 7 Plan 05 — Gateway Re-enqueue and CRD-Presence Gating

<objective>
Close the loop between Gateways and routes, and make every watch this phase adds
survive a cluster that does not have the CRD behind it.

Purpose: without the field index and Gateway watch, a Gateway that gains or
changes an address never propagates to the routes that depend on it (GW-02).
Without CRD-presence gating on *every* registered kind — including the `Gateway`
watch clause, which the 2026-06-07 plan doc leaves ungated — enabling this feature
on a partially-installed cluster crashes the whole operator process (GW-03).
Output: the parentRef field index, the Gateway map function, per-kind RESTMapper
gating, and a gated Gateway watch.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cluster CRD inventory → operator startup | Which CRDs are installed is outside the operator's control and can change between deployments |
| Kubernetes API server → operator informer cache | All informers registered on a manager start together; one unresolvable kind fails the whole cache |
