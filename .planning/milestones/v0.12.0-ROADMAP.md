## Summary

Closed two long-standing defects in the post-edit hook mechanism, both of which
failed silently: hook metrics that were implemented but unreachable, and hook
execution that blocked the gRPC write path.

Single-phase milestone. Split out of v0.11.0 (K8s-Native Automation, phases 7–8)
on 2026-07-31 once release-please cut v0.11.0 after phase 8 while the milestone
still claimed phase 9. Phase 9 is server-side observability rather than operator
parity, so the split is thematic as well as procedural.

## Phase

### Phase 9: Hook Reliability & Metrics

**Goal:** Post-edit hooks are observable and cannot stall the write path.
**Requirements:** HOOK-01, HOOK-02
**Plans:** 5/5 across 4 waves
**Completed:** 2026-07-31

**Success Criteria:**

1. ✅ Each `on_success` / `on_failure` hook execution emits count, duration, and outcome metrics
2. ✅ A per-hook timeout is configurable (no longer a fixed 30s) and hook execution is bounded so a slow hook cannot block write processing

**Plans:**

- `09-01` — Tracer: end-to-end detached hook run with a config-resolved timeout and a recorded execution metric (wave 1)
- `09-02` — Config: `[hooks] default_timeout` resolution chain, positivity invariant, validation and TOML encoding edges (wave 2)
- `09-03` — Metrics: timeout-vs-failure status classification and the `router_hosts_hook_runs_coalesced_total` instrument (wave 2)
- `09-04` — Runner: coalescing accounting, conservation law, bounded drain-then-cancel shutdown (wave 3)
- `09-05` — Docs: operations guide, configuration reference, and the phase CI gate (wave 4)

## Key Accomplishments

1. **Closed a silent dead-metrics gap.** `Metrics.RecordHookExecution` was fully
   implemented against live OTel instruments but had *zero callers* —
   `serve.go` constructed the hook executor before `metrics` existed, so there
   was nothing to wire it to. Now wired, and guarded by a behavioral regression
   test (`TestConfigureMetricsAndHooks_HookExecutorGetsRealMetrics`) that goes
   red if the construction order ever flips back.

2. **Removed hook latency from the write path.** Hooks ran inline in
   `regenerateOutputs`, called synchronously from `AddHost`, `UpdateHost`,
   `DeleteHost`, `ImportHosts` and `RollbackToSnapshot` — N hooks added N×30s to
   every write RPC. Hooks now run on a detached background runner; write RPCs
   return as soon as output files are written.

3. **Made hook timeouts configurable.** Per-hook `timeout` plus a server-level
   `[hooks] default_timeout`, as Go duration strings, resolved once at config
   load across both hook lists. Absent or `"0s"` inherits; negative is rejected.
   Existing configs are byte-identical in behavior.

4. **Made backpressure observable rather than lossy.** Pending work is bounded
   at depth 1 with coalescing, and superseded runs are counted on a dedicated
   `router_hosts_hook_runs_coalesced_total` instrument — so
   `router_hosts_hook_executions_total` stays a truthful count of runs that
   actually executed a command. The conservation law
   `executed + coalesced == triggered` is asserted deterministically.

5. **Made timeout a first-class outcome.** `status` ∈ `success` / `failure` /
   `timeout`, with the classifier checking `hookCtx.Err()` *before* the process
   exit error — because a context-killed subprocess returns an ordinary-looking
   `*exec.ExitError`, and the naive ordering would have recorded every timeout
   as a generic failure.
